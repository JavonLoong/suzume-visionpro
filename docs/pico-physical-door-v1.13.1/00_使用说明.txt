铃芽之旅·实体门联调 1.13.1

这次修了什么
原来的程序在门的四个角还没准备好时就开始画门框，导致启动报错，后面的提示和 X 定位入口也没能准备好。
现在空数组、少于或多于四个点、无效坐标、四个零点都回到默认矩形；已经变形的门框也会恢复。
有效的四个角仍可独立调整，微调模式保留 A/X 选点、B 取消。

安装包
SuzumePortal-PICO-PhysicalDoor-v1.13.1.apk
包名：com.suzume.portal.bletrial
应用显示名称：铃芽之旅·实体门联调
这是独立联调应用，正式版 com.suzume.portal 和旧版 com.suzume.portal.old 保留。
如果头显已有其他电脑签名的同包名联调版，可能提示签名不一致；安装脚本会停止，不会自动卸载或清空数据。

使用
1. 开机后允许相机及“附近设备”权限。主控按现有方式通电，不需要系统蓝牙配对。
2. 准备界面：右扳机识别；左手柄 X 进入手动定位。
3. 手动定位按界面依次记录四个内角。绿框对齐后按右扳机确认，进入浏览。
4. 浏览界面：主控连接且读回“已标定、位置有效”后，右 A 开门、右 B 复位。先松开按键，再重新按下。
5. “开门中／复位中”表示主控已下发目标；“开门到位／复位到位”只在收到对应到位回复后显示。
6. 按右摇杆进入微调；A/X 选整体或四角，左摇杆左右/前后，右摇杆上下，Y 切换步长，右扳机保存，B 取消。
7. 微调期间 A/B 不会控制实体门；退出、恢复追踪或完成动作后，须先松开 A/B 才能再次动作。

连接方式
默认按服务 UUID 扫描 SuzumeDoor 主控；连接后订阅回复，再查询状态。断线清空旧请求，重连只查询，不补发开门/复位。
现场扫描仍超时时，可以通过 install-trial.ps1 的 -BoardAddress 参数输入已确认的主控地址。
主控地址没有写死在 APK 中。未装门扇的空载参数、到位容差均由主控原固件负责，本包不改板端固件或角度参数。
虚拟门洞的定位和实体侧开门是本次联调的两项功能；尚未实现虚拟门扇角度与实体舵机连续同步。

Windows 安装（头显方便连接时再执行）
powershell -ExecutionPolicy Bypass -File .\install-trial.ps1
指定已确认的主控地址时，在后面追加 -BoardAddress "XX:XX:XX:XX:XX:XX"。
脚本只安装并启动联调应用，连接后查询状态，不会自动开门或复位。

验证范围
查看 01_测试结果.txt 和 version.json。

电脑测试通过不代表真机适配已经验收。后续顺序：冷启动/X 定位 → 连接与无动作查询 → 现场确认机构动作范围 → A/B 与匹配的到位回执 → 断线与微调退出不误触发。
